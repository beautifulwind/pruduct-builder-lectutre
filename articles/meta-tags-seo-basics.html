검색 노출을 위한 기본 메타 태그와 sitemap

글: beautifulwind · 2026년 10월 29일 · 검색 최적화

검색 결과에 내 페이지가 어떻게 보일지는 상당 부분 <head> 안의 몇 줄이 결정합니다. 화려한 기법보다 먼저 챙겨야 할 기본 태그와 파일을 실제 예시와 함께 정리했습니다.

목차
  1. title: 가장 중요한 한 줄
  2. meta description
  3. canonical로 중복 정리하기
  4. 공유 미리보기(Open Graph)
  5. robots.txt와 sitemap.xml
  6. 태그보다 중요한 것

title: 가장 중요한 한 줄

<title>은 브라우저 탭과 검색 결과의 파란 제목으로 쓰입니다. 새 HTML 파일을 만들면 편집기가 자동으로 넣어 주는 <title>Document</title>를 그대로 두는 경우가 의외로 많은데, 이 상태로는 검색 엔진도 사용자도 페이지 내용을 알 수 없습니다.

  • 페이지마다 서로 다른 제목을 씁니다. 모든 페이지 제목이 사이트 이름뿐이면 검색 결과에서 구분이 되지 않습니다.
  • 핵심 내용을 앞에 두고 사이트 이름은 뒤에 붙입니다. 예: GitHub Pages로 정적 사이트 배포하기 | 사이트 이름
  • 검색 결과에서는 긴 제목이 잘리므로, 앞부분만 읽어도 의미가 통하게 씁니다.

meta description

<meta name="description" content="저장소 준비부터 사용자 지정 도메인 연결, 경로 문제 해결까지 GitHub Pages 배포 과정을 정리합니다.">

설명은 검색 결과에서 제목 아래 회색 문장으로 노출될 수 있습니다. 검색 엔진이 본문에서 더 적절한 문장을 골라 대신 보여 주기도 하므로 순위를 직접 올리는 장치라기보다는, 사용자가 클릭할지 판단하는 데 도움을 주는 요약문으로 생각하는 편이 정확합니다. 페이지마다 실제 내용을 한두 문장으로 요약하고, 키워드를 억지로 반복하지 않습니다.

canonical로 중복 정리하기

같은 페이지가 여러 주소로 열리는 일은 흔합니다. /와 /index.html, 끝에 추적용 파라미터가 붙은 주소 등이 그렇습니다. 이때 대표 주소를 알려 주는 태그가 canonical입니다.

<link rel="canonical" href="https://example.com/articles/github-pages-deploy.html">

canonical은 상대 경로가 아닌 전체 주소로 적고, 실제로 열리는 주소를 가리켜야 합니다. 존재하지 않는 주소나 다른 내용의 페이지를 가리키면 오히려 혼란을 줍니다.

공유 미리보기(Open Graph)

메신저나 SNS에 링크를 붙였을 때 나타나는 제목과 설명은 Open Graph 태그에서 가져옵니다.

<meta property="og:type" content="article">
        <meta property="og:title" content="GitHub Pages로 정적 사이트 배포하기">
        <meta property="og:description" content="저장소 준비부터 도메인 연결까지">
        <meta property="og:url" content="https://example.com/articles/github-pages-deploy.html">

대표 이미지를 지정하는 og:image는 전체 주소로 적어야 하며, 지정하지 않으면 서비스에 따라 미리보기에 이미지가 표시되지 않습니다.

robots.txt와 sitemap.xml

robots.txt는 검색 로봇에게 수집해도 되는 범위를 알려 주는 파일이고, sitemap.xml은 사이트에 어떤 페이지가 있는지 목록으로 알려 주는 파일입니다.

User-agent: *
        Allow: /

        Sitemap: https://example.com/sitemap.xml

robots.txt는 ads.txt와 마찬가지로 도메인 최상위에 있어야 효력이 있습니다. 사이트맵은 페이지가 몇 개 안 되는 작은 사이트에서도 새 글을 빠르게 알리는 데 도움이 되며, Google Search Console에 사이트맵 주소를 제출하면 수집 현황과 오류를 확인할 수 있습니다.

주의할 점은 robots.txt가 보안 장치가 아니라는 것입니다. 파일 내용은 누구나 볼 수 있고, 수집을 막아도 다른 곳에서 링크되면 주소가 노출될 수 있습니다. 공개하면 안 되는 내용은 애초에 공개 저장소에 올리지 않아야 합니다.

태그보다 중요한 것

태그는 페이지를 정확하게 소개하는 역할을 할 뿐, 내용이 부족한 페이지를 좋은 페이지로 바꿔 주지는 않습니다. Google이 공개한 고품질 사이트에 관한 질문들도 결국 다음과 같은 내용으로 모입니다.

  • 이 글의 정보를 신뢰할 수 있는가, 주제를 잘 아는 사람이 썼는가
  • 다른 페이지를 옮기거나 조금 바꾼 것이 아니라 독창적인 분석과 정보가 있는가
  • 검색 결과의 다른 페이지와 비교해 더 많은 가치를 주는가
  • 맞춤법과 사실 관계를 꼼꼼히 확인했는가
  • 광고가 본문을 가릴 만큼 많지 않은가
  • 친구에게 공유하거나 북마크하고 싶은 글인가

제목, 설명, canonical을 바르게 달고, 그 위에 읽는 사람의 문제를 실제로 해결해 주는 글을 쌓아 가는 것. 이것이 검색 최적화의 가장 확실한 기본입니다.
